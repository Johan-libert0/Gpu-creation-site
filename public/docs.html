Configuration

Explicit integration controls

Production startup requires a complete Auth0 tenant configuration, verified-email allowlist, HTTPS base URL, PostgreSQL connection, and application encryption key. Secrets belong only in the hosting provider’s secret store. Prompt generation requires Hugging Face Inference Providers credentials and model selection; production also requires review of data-handling terms.

  • AUTH0_DOMAIN, AUTH0_CLIENT_ID, AUTH0_CLIENT_SECRET, AUTH0_SECRET, AUTH0_ALLOWED_EMAILS, BASE_URL
  • Only verified Auth0 email addresses listed in AUTH0_ALLOWED_EMAILS can use production APIs and dashboard functionality.
  • DATABASE_URL and a stable DATA_ENCRYPTION_KEY encoding 32 bytes as hex or base64
  • HF_TOKEN with Inference Providers permission, HF_MODEL, and GPU_PROVIDER_PRIVACY_ACKNOWLEDGED=true after reviewing data-handling terms
  • PostgreSQL stores job/payment metadata and encrypted pending prompts. The PostgreSQL-backed queue supports durable retries and multi-instance worker claims.
  • The Render Blueprint uses Free web and PostgreSQL plans and sets X402_ENABLED=true. Direct paid generation and browser-wallet checkout use x402 and require a receiving wallet, CDP facilitator credentials, verified USDG token metadata/transfer method, durable PostgreSQL receipts, and available inference. This does not enable marketplace escrow or provider payouts.
  • Render Free web services can sleep when idle, and Free PostgreSQL expires after 30 days without backups. Use this only for testing; external inference or facilitator usage may still cost money.
Security and payments

How security and payments work

Account access: In production, Auth0 handles sign-in. APIs require an authenticated session and a verified email on the configured allowlist; marketplace records are scoped to the signed-in buyer or provider. Passwords are handled by Auth0, not stored by this app. Server credentials belong in the hosting provider’s secret store.

Prompt handling: Accepted marketplace prompts are encrypted with AES-256-GCM while queued in PostgreSQL, then sent by the server to Hugging Face Inference Providers for generation. The selected inference provider controls its own processing and retention. Encryption during queue storage is not a secure-deletion guarantee; do not submit confidential prompts unless the provider’s terms are suitable.

Direct-generation payment: The separate x402 endpoint charges 0.01 USDG on Arbitrum One for a successful response. A supported browser wallet signs the payment authorization, the CDP facilitator verifies and settles it, and the service records a deduplicated receipt in PostgreSQL. Payment configuration, facilitator support, inference availability, and receipt storage must all be working for the flow to complete.

Marketplace payments: A proposed job payout is an indicative record only; posting or approving a marketplace job does not transfer funds. The x402 direct-generation flow is not marketplace escrow and does not pay providers. The separate escrow contract in the repository is a local test project, not part of the deployed payment flow.

Hosting: The Render Blueprint enables x402 on Free plans. Free web services can sleep, and Free PostgreSQL expires after 30 days without backups. Inference and facilitator usage may incur charges.
