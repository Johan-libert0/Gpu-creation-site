Configuration

Explicit integration controls

Production startup requires a complete Auth0 tenant configuration, verified-email allowlist, HTTPS base URL, PostgreSQL connection, and application encryption key. Secrets belong only in the hosting provider’s secret store. Prompt generation requires Hugging Face Inference Providers credentials and model selection; production also requires review of data-handling terms.

  • AUTH0_DOMAIN, AUTH0_CLIENT_ID, AUTH0_CLIENT_SECRET, AUTH0_SECRET, AUTH0_ALLOWED_EMAILS, BASE_URL
  • Only verified Auth0 email addresses listed in AUTH0_ALLOWED_EMAILS can use production APIs and dashboard functionality.
  • DATABASE_URL and a stable DATA_ENCRYPTION_KEY encoding 32 bytes as hex or base64
  • HF_TOKEN with Inference Providers permission, HF_MODEL, and GPU_PROVIDER_PRIVACY_ACKNOWLEDGED=true after reviewing data-handling terms
  • PostgreSQL stores job/payment metadata and encrypted pending prompts. The PostgreSQL-backed queue supports durable retries and multi-instance worker claims.
  • The Render Blueprint sets X402_ENABLED=true. Direct paid generation and browser-wallet checkout use x402 and require a receiving wallet, CDP facilitator credentials, verified USDG token metadata/transfer method, durable PostgreSQL receipts, and available inference. This does not enable marketplace escrow or provider payouts.
Security boundaries

What is not production-ready

Production APIs require Auth0 sessions and return jobs and payments scoped to the signed-in buyer or provider. Prompts are encrypted in PostgreSQL while queued and are sent to Hugging Face Inference Providers after acceptance. The inference provider may process or retain prompts under its own terms; this is not a secure deletion guarantee or a production privacy guarantee. Acknowledging terms does not certify the provider. Provider privacy validation and independent security review remain outstanding. Marketplace job payment records remain unpaid; x402 direct-generation payments are separate.
